# GPX 三维轨迹应用：产品与技术规划 v1.1

修订日期：2026-09-28。依据：用户提供的《规划方案 v1.0（已确认决策）》及本次官方资料核查。

状态：已按用户授权开始开发。原文中的“已确认、进入开发”作为历史记录；本次已确认的产品边界见 1.2 节。2026-09-28 补充执行顺序：先完成电脑浏览器可交互原型，再做 Android 最小真机验证，之后完成户外首版。浏览器预览不等同对外发布 Web 产品，不能替代 S0 真机门槛。当前已建立 v0.1 浏览器工程，尚无 APK 或真机验收。

## 1. 评审结论与方向调整

保留 **Android 优先、Flutter + WebView + CesiumJS** 作为首选验证路线。最需要调整的是产品能力边界，而不是立即换引擎。

定位：**面向自己和少量朋友的户外 GPX 行进辅助工具：出发前三维看路线，途中低功耗跟轨迹、提醒偏离。** 主要使用地区为中国大陆。将三个场景明确分开：

1. **三维预览与复盘**：理解路线、海拔和关键节点，是首版的行前准备能力。
2. **到达起点或选定目的地**：调用高德按道路网络规划，明确展示目的地。
3. **沿 GPX 行进**：保持导入路线，做当前位置、路线进度、偏离提醒；由独立轨迹引导模块实现，不默认由高德重新算路替代。

高德当前 Android 步行/骑行指南展示起终点算路，且要求联网。它不能作为“传入 GPX 关键点就能严格沿原轨迹导航”的依据。因此删除原方案中的这个技术承诺；如果后续供应商提供相应专用能力，须以具体版本、授权和样例验证后再纳入。[高德官方指南](https://developer.amap.com/api/android-navi-sdk/guide/route-plan/ride-route-plan)

### 1.1 原方案主要修订

| 原方案问题 | v1.1 处理 |
|---|---|
| 任意 GPX 等同高德导航路线 | 分离道路导航与轨迹引导；高德不改变原轨迹 |
| 不做离线包，却承诺缓存区断网看三维 | 不承诺离线三维；本地轨迹、统计和无底图二维视图可离线打开 |
| 解析后立刻抽稀并统计 | 原始、分析、显示数据分离，显示抽稀不影响统计 |
| GPX 全部当单条折线 | 保留多轨、多段、路线点、航点及来源；断段不连接、不计跨段距离 |
| 地形贴地高度等同真实海拔 | 原始高程与地形估计分列；高程来源、质量、算法版本可追溯 |
| WebView 负责唯一解析、统计 | 解析/分析独立于渲染生命周期，首版推荐 Dart isolate |
| 高德影像直接叠加到 Cesium | 删除；单独展示高德原生视图，避免瓦片授权与坐标配准问题 |
| 建筑白模与户外核心功能同时推进 | 延后，先做剖面联动、路线预览、航点与稳定性 |
| “30fps、不被杀、误差 <5%” | 改为设备、场景、算法和统计口径明确的验收 |
| 密钥放原生层即安全 | 客户端凭据按可提取处理，使用最小权限、应用限制及轮换 |
| 法务/数据源风险留到商业化前 | S0 就核查适用授权、来源和目标地区可用性，公开发布前再完成发布审查 |

### 1.2 本次用户已确认的产品边界

- 首版必须支持户外沿 GPX 行进及偏航提醒。
- 近期个人或少量朋友自用，主要中国大陆。

因此，定位、断网本地轨迹、锁屏提醒及后台恢复纳入首版门槛；动画预览与建筑后置。先使用固定签名 APK 小范围分发，不将商店上架列为首版交付。数据和 SDK 授权仍需核查，自用不自动免除供应商条款。

## 2. 首版范围与用户流程

### 2.1 P0：行前准备

流程：导入 → 检查轨迹质量/选择轨道 → 概览 → 三维查看与剖面联动 → 保存到本地轨迹库 → 再次打开。

- 系统文件选择及分享导入；导入失败说明原因，超限文件可取消，不冻结界面。
- 原始 GPX 本地保留；轨迹库支持重命名、删除、重复导入提示与重新打开。
- 多轨选择、多段保留、起终点和基础航点名称展示。
- 三维贴地轨迹、缩放旋转、全线适配、回到全览、当前选点定位。
- 剖面拖动与地图选点双向联动；显示累计距离、可用高程和来源。
- 总距离、累计升降、总历时（时间完整且有效时）、数据质量提示。
- 首版通过剖面拖动查看沿线位置；自动播放、速度调节和跟随镜头列入 P1。无时间戳时后续播放标记“模拟预览”，不虚构真实速度。
- 地形/影像加载中、失败、鉴权错误、断网、WebGL 不可用时有明确状态。
- 本地无底图二维路线和剖面作为降级展示，不把椭球视图标为真实山地。
- 可选便捷入口“用高德前往起点”，不标为“沿此轨迹导航”；未安装、启动失败有提示。

### 2.2 P0：实地轨迹引导

流程：打开已保存路线 → 选择行进方向/起始段 → 检查定位与权限 → 开始引导 → 锁屏/前台持续提醒 → 暂停或结束。

当前位置、定位质量、已行进/剩余距离、偏离提醒、正向/反向行进、后台定位与恢复全部为 P0。行进页默认轻量二维路线，提供比例尺、朝向、定位时间和精度，三维按需打开。没有底图时清楚标记“仅轨迹”，不表示周边道路或可通行区域。偏离提醒支持声音/振动及停止提醒，不要求持续盯屏。多段缺口不推断可通行连接，不将跨段距离计入剩余里程。

基础航点提醒列 P1，优先于照片挂点。高德内嵌道路导航单独评估，避免它成为轨迹引导的依赖。

### 2.3 后续能力

P1：自动沿线预览、航点提醒、坡度着色、按实际需要评估授权离线底图与内嵌道路导航。P2：建筑白模、照片、FIT/TCX、录制、云同步、iOS、Web、实景三维。正式版不以“做完全部 P2”作为条件；稳定完成承诺的范围即可形成正式版本。

MVP 不引入账号和业务后端；先使用本地数据。正式公开发布所需网站、隐私说明或供应商配置另行评估。

## 3. 架构与备选路线

电脑预览阶段采用 TypeScript + Vite + Cesium，使用 Web Worker 解析、IndexedDB 保存，定位通过适配接口接入模拟器或浏览器。以下 Flutter/Android 分层仍为移动端目标；桌面版先验证渲染、数据协议与测试向量，原生定位和提醒随后独立验证。当前实现与证据见《阶段验证-v0.1.md》。

```text
Flutter：轨迹库、详情、剖面、权限、加载/错误状态
  ├─ 文件导入 → Dart isolate 解析/分析 → 本地文件 + SQLite
  ├─ 版本化消息桥 → WebView/Cesium：绘制、相机、选点、预览
  ├─ 本地二维视图：无网/三维故障降级
  └─ Android 原生适配层：定位前台服务、轨迹匹配、提醒、外部高德入口
```

### 3.1 数据所有权

- 应用数据层是唯一事实来源，WebView 可以销毁、重建，不丢轨迹和统计。
- 原始层：GPX 字节、哈希、导入时间、源信息和原始点；不覆盖用户数据。
- 分析层：有效点标记、分段距离、质量信息、统计、算法版本、高程来源。
- 显示层：按缩放级别生成的抽稀线与图表数据，保存回原始点/区间的映射。
- 后续 Web 复用渲染模块和数据协议；Dart 核心不会天然被 TypeScript 复用，需另行评估 Dart Web 或共享规范/测试向量。不要承诺“全部代码直接复用”。

### 3.2 桥接及资源加载

- Flutter ↔ JS 使用 WebView 插件提供的通信接口；Flutter ↔ Kotlin 使用平台通道。两者不是同一条 MethodChannel。
- 协议包含 schemaVersion、requestId、routeId、generation、type、payload；支持 ready、ack、error、进度、取消和超时。
- 大文件不在 UI 线程 DOMParser 一次性解析，不用 JS 字符串拼接执行 GPX 内容。传递结构化、分块的显示数据，限制消息体与在途数量。
- 切换路线使旧请求失效，避免迟到结果覆盖当前路线；桥只向受信任本地页面开放，外部导航受限。
- 打包固定版本的 JS、Workers、Widgets 等资源，S0 验证本地资源 origin、CORS、Worker 路径及请求凭据；禁止依赖公共 CDN 才能打开页面。
- 数据库 schema 有迁移版本；导入使用临时文件与事务，失败不留下半条记录。删除轨迹时同步处理派生数据。

### 3.3 引擎选择门槛

Flutter + CesiumJS 是首选试验方案，不是未经测试的性能结论。删除原文未实测的引擎帧率、内存和空包大小对比。

若经过降低渲染分辨率、地形细节、轨迹点数等优化仍不达标：先缩小最低支持设备/降低画质；若仍失败，评估适合地形展示的原生渲染方案或 Android 原生壳。Unity/Unreal 仅在确有沉浸三维需求和对应开发能力时做独立原型，不自动升级为兜底。

## 4. GPX、统计与高程规则

### 4.1 解析与质量

兼容 GPX 1.0/1.1、默认/带前缀命名空间、trk/trkseg、rte、独立 wpt、UTF-8 BOM；未知扩展可忽略但原文件保留。GPX 规范采用 WGS84 与米制单位。[GPX 1.1](https://www.topografix.com/gpx/1/1/)

- 不把多段断口连成真实行程；rte 是路线控制点，不默认等同密集记录轨迹。
- 校验经纬度范围、有限数值、空文件、单点、重复点、异常时间和跳点；不悄悄“修好”无法判断的数据。
- 缺高程不填零；缺时间不生成实际时长/速度。时间缺口、逆序、停留和断段独立标记。
- 禁用 DTD/外部实体和外部 schema 加载；限制文件字节数、点数、XML 深度及文本长度，防止内存耗尽。
- S0 暂测 1 万、5 万、20 万点和 20MB 文件。最终支持上限由实测冻结；超限明确拒绝或分轨导入，不用静默抽样冒充完整导入。

### 4.2 统计口径

- 默认距离：各有效连续段内相邻点的 WGS84 水平测地距离之和；不计段间直线。
- 总历时：仅对时间完整且单调的段计算并说明断段口径。移动时间暂不作为 P0 指标，避免引入隐藏停留阈值。
- 累计升降：以分析数据计算，记录高程来源、距离窗口、去噪/滞回阈值及算法版本。S0 用参考样例确定参数，不依赖屏幕显示抽稀。
- 剖面横轴为累计距离；图表降采样保留重要极值，点选映射回分析数据。
- 最大坡度对 GPS 噪声敏感，延至 P1；使用固定距离窗口并显示计算尺度，不直接用相邻两点的极值。
- 地形夸张系数只影响视觉，不能修改统计；桥梁、隧道、悬崖附近贴地显示与真实经过高度可能不同。

### 4.3 高程来源

原文件 ele 优先保留，另列 DEM 估计；来源不明时显示未知垂直基准，不假设所有导出设备高程都能与 Cesium 地形直接对齐。高程缺失可按需联网补充，记录数据源、分辨率/可用信息和采样日期，失败可跳过。

不混合不同来源后给出未经说明的“准确爬升”。高程补充是估计值；用户能看见原始统计与估计统计的区别。

## 5. Cesium 渲染与资源控制

- 首版只加载地形、授权影像、路线和少量标记，不加载建筑。
- 简单贴地线使用 Entity 的 PolylineGraphics.clampToGround；大数据再基准测试 GroundPolylinePrimitive。SampledPositionProperty 可用于预览位置采样，不等同贴地线渲染。[PolylineGraphics](https://cesium.com/learn/cesiumjs/ref-doc/PolylineGraphics.html)
- 显示抽稀在每一段独立执行，采用米制误差，保留端点和关键节点；不直接把经纬度角度当米。
- 静止时按需渲染，交互/播放时请求帧；限制像素比和高耗能特效。暂停或离开页面时停止动画与不必要请求。
- 地形/影像、3D Tiles、WebView 进程内存分开监控。当前 3D Tiles 使用 cacheBytes 与 maximumCacheOverflowBytes 等参数；它们不是整个应用或地形的硬内存上限。原文 maximumMemoryUsage 不作为新实现的统一策略。[Cesium3DTileset](https://cesium.com/learn/cesiumjs/ref-doc/Cesium3DTileset.html)
- WebGL context lost 或 WebView 渲染进程异常时，先保存状态，再按实际可恢复性重建 Viewer/WebView；连续失败切二维。监听事件本身不能保证自动恢复成功。
- 三维与原生地图不默认双实例常驻；离开时释放重资源，保留路线、镜头和选点状态。

## 6. 地图源、坐标、网络与授权

### 6.1 坐标边界

内部地理数据采用 WGS84，所有外部坐标携带 CRS 标识。高德展示/接口边界采用该接口要求的坐标与官方转换能力；返回数据保留来源和坐标系，禁止对同一坐标重复转换。

大陆外使用范围及覆盖独立验证。不要用“仅转换折线顶点”去解决 GCJ-02 栅格影像与 WGS84 三维地形的配准问题。首版不接未授权瓦片 URL，不在 Cesium 上混搭高德瓦片。

### 6.2 在线与离线边界

- ion 先用于技术验证，记录目标网络下地形/影像成功率、首屏时间、失败类型及流量。
- 本地轨迹/统计/剖面/无底图二维路线离线可用；未下载的地形、影像、道路算路不可假定可用。
- 不自建 ion 地形下载器或专用持久瓦片缓存作为 MVP；授权核查前不承诺缓存保留时长和离线区域。ion 条款对离线使用与一般性能缓存有不同规定，具体数据集/套餐需分别核查。[ion 服务条款](https://cesium.com/legal/terms-of-service/)
- 地形失败独立于 GPX 导入失败；允许重试、取消与退回二维，禁止无限等待和无界重试。
- 需要可靠离线底图时，先确认具备离线使用权的数据，再单独设计下载范围、大小、更新和存储预算；自托管不是现有在线数据授权的自动延伸。

### 6.3 凭据、成本与发布

- Cesium 使用单应用、最小 assets:read 权限及指定资产范围的 token；不把管理/写权限 token 放客户端。URL 限制在本地 WebView origin 下是否适用必须实测，不能直接假定有效。[token 官方指南](https://cesium.com/learn/ion/cesium-ion-access-tokens/)
- Android Key 按供应商要求配置包名与签名；开发、发布签名分别核验。原生层中的 Key 仍可被提取。
- 记录具体资产 ID、供应商、版本、署名要求、适用套餐、额度和超额处理。地图署名在移动端也保持可见；不预设“免费额度足够商用”。
- S0 实测单次路线浏览的数据量，再按活跃用户 × 使用次数 × 单次流量估算月成本；按小范围自用估算，具体人数和预算待明确，计划内留出配额告警与停用/降级开关。
- 大陆公开发布前核查地图内容、审核/资质的适用要求及数据服务安排。不能将“用公开 DEM”或“接入高德”当作整个应用合规结论；适用性需按实际服务确认。[地图管理条例](https://www.gov.cn/zhengce/zhengceku/2015-12/14/content_10403.htm)
- GPX 默认本地处理，不上传原文件；错误日志不包含整条轨迹、精确位置或 token。地图请求仍会向服务商暴露请求区域，隐私说明需覆盖实际 SDK 与网络行为。

## 7. P0 沿轨迹行进设计

此模块和道路导航分开验收，是首版核心门槛；仅完成三维展示不能交付为可实地使用的首版。

- 原生 Android 定位适配作为离线 WGS84 数据基线，S0 对目标手机验证 GNSS 定位、首次定位时长与耗电；需要高德定位增强时单独适配，保留 GCJ-02 等来源标记，不能混入 WGS84 匹配流程。
- 前台服务持有当前路线的匹配数据并执行偏离判断/提醒，不依赖 Flutter 页面定时器。UI 订阅服务状态；路线和会话进度持久化，进程重建后明确显示“引导已中断/待恢复”，不假装期间持续工作。

- 定位和轨迹匹配放在原生/应用层，不依赖 Cesium 或 WebView 保活。
- 用到线段的距离判断偏离，结合定位精度、速度、连续样本和持续时间；建立进入/退出偏离的滞回，降低定位飘移的误报。
- 用历史进度和方向限制候选线段，处理发卡弯、平行山路、环线、自交和往返路线。不能只找全局最近轨迹点。
- 弱精度、过期位置或无定位时显示不确定状态，不宣称已偏航或安全到达。
- 语音先做“偏离路线、接近航点”等有依据的提示；没有路口语义时不虚构逐路口转向口令。
- 偏离后提示原轨迹位置，不自动规划一条穿越未知地形的回归路线；道路重新算路由用户明确进入高德功能。
- Android 按适用版本配置 location 前台服务、运行时权限及启动时机。拒绝权限、锁屏、省电、进程被终止后有清楚的状态和恢复流程；不承诺永久不被杀。[Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#location)
- 断网时保留本地路线、统计和可用设备定位；必须测试真实设备的离线首次定位与持续定位，不能把断网等同定位必然成功。
- 退出引导停止定位与播报。三维仅按需查看，减少长时间导航发热和耗电。

## 8. 里程碑与验收

模块使用功能名称，里程碑使用 S0/S1/S2，避免原文 M1/M2 同时指模块与阶段。

| 阶段 | 交付 | 出口门槛 |
|---|---|---|
| S0 风险验证 | APK 原型、数据样例、设备/网络报告、依赖版本记录 | 三维、离线定位、锁屏提醒、网络源及授权前提均有证据；不合格先调整路线 |
| S1 首版功能候选 | 轨迹库、统计、剖面联动、二维行进、匹配、偏离提示、后台服务 | 全部 P0 可完成，关键错误可恢复，不依赖开发机或 CDN；尚未作为户外正式内测包 |
| S2 首版户外验收 | 固定签名 APK、实测记录、已知限制与恢复说明 | 完成位置回放、锁屏/断网及实际步行或骑行测试后，向少量朋友分发 |
| 发布门槛 | 稳定安装包、已知限制、适用发布材料 | 依据实际承诺发布，不要求做完后续功能 |

没有已知团队与可投入时间，不沿用原文 2.5 人配置和固定总工期。S0 建议以 5–10 个实际开发人日作为第一轮时间盒；届时拿实测与剩余风险重新估算，不视为交付保证。

### 8.1 S0 测量与建议目标

以下数值是待实测校准的验收目标，不是已达成结果：

- 设备：至少 1 台中端 Android 与 1 台较低配置 Android，登记型号、系统、RAM、GPU、WebView 版本；iOS 暂不进入首发矩阵。
- 数据：1 万/5 万/20 万点，单轨、多段、无高程、无时间、自交、环线、极端边界及损坏文件；尺寸上限测试同时测峰值内存。
- 导入：中端机 5 万点本地解析与统计目标 ≤3 秒；UI 可响应、可取消。三维瓦片加载时间单独统计。
- 交互：固定镜头操作脚本下，中端机 1 万显示点目标 p95 帧耗时 ≤33.3ms；低配可降级，记录卡顿、温升和耗电。静止按需渲染不按持续 30fps 验收。
- 稳定性：连续交互 30 分钟、切换轨迹/页面 20 次、前后台切换及三维重建。记录宿主与可测 WebView 渲染进程 PSS、JS/GPU 可用指标，不只看 Dart heap。
- 内存：区分瓦片缓存填充与泄漏；重复同一路线稳定操作后检查回收趋势，S0 根据最低支持设备冻结峰值预算，不把 256–512MB 作为通用安全值。
- 网络：至少 Wi-Fi、移动网络、限速/高延迟和断网；分别测冷加载与热加载，多次采样记录中位与 p95。超过设定等待阈值可切二维，超时值由 S0 确定。
- 可恢复：鉴权失效、地形请求失败、WebGL/渲染进程异常、导入取消、磁盘不足后，已保存数据可重新打开。

### 8.2 数据与行为验收

- 固定算法的合成样例与独立参考实现核对：水平距离建议误差 ≤0.1% 或 1 米取较大者；这是计算一致性测试，不代表 GPS 测量精度。
- 高程原值解析不被改写；累计升降以已冻结算法的金样本验证。第三方 App 统计仅作为对照，不能用统一 5% 判定对错。
- 缩放改变、轨迹抽稀、二维/三维切换不会改变同版本统计结果。
- 多段不误连、多轨选择正确，缺失值不变零；有日期变更线轨迹时检查包围范围与抽稀。
- 坐标转换使用明确来源的参考点做数值回归，测两视图各自的坐标契约；实地对齐另记录 GPS、底图和转换误差，不能只靠肉眼。
- S2 用已知位置序列回放验证自交、往返、飘移、丢定位及持续偏离；偏离阈值与提醒延迟共同记录后冻结。真机锁屏至少 60 分钟并观察耗电；系统终止服务时验证恢复，不把“不被杀”作为绝对承诺。

## 9. 启动前输入与下一步

已确认首版需户外行进/偏航提醒，个人或少量朋友在中国大陆使用。实施时补充常用手机型号、3–5 条可脱敏 GPX、主要活动类型、预期团队/时间与地图预算。缺少真实样例时先用合成数据验证，不将合成结果当作户外通过。

S0 实施顺序：

1. 确定样例、最低候选设备、依赖版本和性能记录模板。
2. 建立最小 Flutter/WebView/Cesium 原型，验证本地资源、地形影像访问、镜头交互及二维降级；同时验证原生定位前台服务在锁屏和断网下运行。
3. 实现独立 GPX 解析/分析与桥接，测试分段、缺字段、大文件和取消。
4. 做贴地线、选点/剖面联动、二维定位匹配与声音/振动提醒；运行固定真机脚本和锁屏测试，动画预览后置。
5. 验证高德“前往起点”入口的坐标、未安装和失败路径；若要求内嵌道路导航，单独做 SDK 能力验证。
6. 产出风险关闭表与继续/调整建议，再冻结 S1 范围和工期。

凭据在本地配置中提供，不要求在聊天粘贴。缺 token 时可以先验证解析、二维与合成地形流程，但不能据此声称真实在线地形已经通过。
