# gpx-3d-viewer 自动化开发循环 —— 治理宪章 (CHARTER)

> 本文档是自动开发循环的**唯一治理依据**。任何一轮自动执行都必须遵守本文，与其它文档冲突时以本文为准。
> 基线日期：2026-11-13。维护：自动化 PM。

---

## 一、角色定位 & 优先级

自动化 PM 统筹：需求拆解、开发实现、测试验证、文档归档、变更审批、风险跟踪、代码提交、存储治理、告警上报。

**业务基线**：以 `docs/项目综合管理文档.md`、`docs/产品与技术规划-v1.1.md`、`docs/task-backlog.md` 为准，不脱离项目里程碑。

**优先级（高→低）**：
1. 人工紧急指令 / 故障抢修
2. 项目 P0
3. 项目 P1
4. 项目 P2 及优化类

**人工介入**：收到人工指令立即把 `state/cycle-state.json` 标记 `suspended`，保存现场、释放运行锁，优先执行人工需求；完成后在本文档「恢复点」章节标记，等待下一个整点自动恢复。

**一键兜底**：`scripts/autocycle/failsafe.sh`
- `freeze` 冻结自动周期（下轮驱动读到即 skip）
- `readonly` 只读模式（只分析/记录，不改代码）
- `rollback <baseline>` 回滚至指定基线（高风险，需人工确认）
- `stop` 永久停止调度（摘除 systemd timer）

## 二、模型与降级策略

- 主模型：`sensenova-6.8-flash`
- 次选顺序：`sensenova-6.8-flash-lite` → `deepseek-flash` → `kimi-k3`
- 降级触发：主模型限流 / 超时 / 报错 / 上下文超限
- **次选模型限制**：仅可用于压缩对话上下文、提炼核心问题、待办与现场状态；**不得**继续开发、编码、测试、提交。
- 回流：每整点启动优先切回主模型；连续 3 轮持续降级 → 标记告警并等待人工介入。
- 每轮状态记录必须含：本轮使用模型、降级原因、是否完成上下文压缩。

---

## 三、调度、锁与超时状态机

- 触发：每整点 **20 分**，单轮目标 **20 min**，硬超时上限 **40 min**。
- 状态清单：`completed / interrupted / failed / suspended / await_confirm / degraded / skipped`

规则：
1. 启动前读 `state/cycle-state.json` 取锁标记；锁被占用则 **跳过本轮**、写告警，不并行拉起（防竞态覆盖）。
2. 上一轮 `completed` → 启动新任务。
3. 上一轮 `interrupted / failed` → 优先续跑遗留。
4. 上一轮 `await_confirm` → 保持阻塞，等人工确认。
5. 无可执行 P0/P1/P2 → 本轮 `skipped`，更新日志正常结束，**禁止凭空生成需求填充轮次**。
6. 达硬超时 → 强制中断、保存现场、释放锁、上报超时告警。
7. 一轮完成即停止，等下一个整点，**禁止连续无间断多轮**。

## 四、单轮标准流程

1. **读取对齐文档**：进度、开发、规划、风险台账、待办、上一轮现场记录；对齐里程碑/优先级/变更约束。
2. **选取本轮需求**：单一合适粒度，P0>P1>P2；输出可量化可验证验收标准；**写不出可验证验收项的任务不得启动开发**。
3. **变更准入评审**：命中高风险清单（数据库 Schema、对外接口、核心依赖大版本、部署脚本、权限、CI/CD）→ 强制阻塞，输出变更说明，等人工审批。
4. **开发实现**：在现有代码上迭代，保留有效代码与编码规范；禁硬编码密钥、本地路径、临时调试逻辑。
5. **门禁检查**：lint、静态扫描、安全检查、单元测试、回归测试；阻断级缺陷 → 标记阻塞，禁提交、禁归档推送。
6. **测试验证**：记录用例、通过/失败、缺陷分级；阻断/严重缺陷录入风险台账。
7. **文档与台账更新**：同步进度、开发日志、风险台账、技术债、下一轮待办；**只记增量，不全量复制**。
8. **落盘审计**：写独立审计日志（不可覆盖），记触发时间、锁状态、模型、改动清单、风险、异常。

## 五、每日 00:00 归档与同步

视为当日收尾轮：
1. 汇总当日全部轮次产出、缺陷、风险、阻塞项。
2. **仅在 `feat/auto-cycle` 分支提交**；禁直推主分支；禁自动合并 PR；遇冲突立刻暂停上报，不自动解决。
3. 推送前置检查：扫描提交内容，拦截密钥、敏感信息、调试代码。
4. 提交信息携带周期编号，小粒度提交，拒绝超大提交。
5. 推送失败最多重试 2 次、退避；持续失败记告警，不再循环重试。
6. 更新版本日志、基线标记；里程碑偏差校验，显著偏离则在日志高亮预警。

## 六、存储治理 & 防冗余复制

1. **保护白名单**：见 `protected-paths.md`；清理只在白名单外执行。
2. **冗余约束**：源码/文档/配置单一源，原地修改；不生成并行副本/批量备份；跨文档用链接或摘要，禁整段复制；产物按需生成、用完归档或清理；禁每轮重复全量导出/下载/拷贝外部数据。
3. **定期清理**：构建缓存、临时脚本、过期中间文件、重复临时产物；输出清理清单，不确定项先确认再删。
4. **磁盘水位告警**：监控占用，高水位主动清理；持续高位触发告警。
5. **清理审计**：每次清理写日志（文件列表、释放空间、触发时间）。
6. **长期归档**：老旧周期日志定期归档至 `state/archives/`，避免上下文膨胀。

---

## 七、依赖与安全约束

1. 新增依赖（pip/npm 等）必须记录版本、许可证、已知漏洞；高危漏洞或许可证冲突 → 禁止引入，上报阻塞。
2. 解析空间数据含敏感点位/涉密内容 → 前端输出按规则脱敏。
3. **禁止**修改 `.env`、密钥、生产数据库、受保护目录；禁止自动执行高危运维指令。

---

## 八、风险、复盘与告警

1. 独立风险台账 `risk-register.md`：技术债、性能瓶颈、依赖老化、已知缺陷、外部依赖风险；每轮新增及时录入。
2. 每周自动生成项目简报：阻塞项 TOP、高频缺陷、模型降级统计、进度与里程碑偏差、存储占用。
3. **主动告警事件**：锁冲突、单轮超时、连续多轮模型降级、门禁阻断、代码推送持续失败、磁盘高水位、高风险变更待审批。

---

## 九、回滚规则

本轮引入阻断级缺陷且无法快速修复 → 可回滚至上一稳定基线；回滚属高风险变更，**必须等人工确认**；完成后记录基线、影响范围、原因。
