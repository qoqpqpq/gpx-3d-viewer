## 1. 项目总览

**更新频率：每次里程碑验收、架构调整或发布时。**

### 1.1 项目定位

面向个人及少量朋友、主要在中国大陆使用的 GPX 路线查看与户外沿轨迹行进工具。

已确认的首版目标：

- 导入、保存、查看 GPX 路线及其统计数据。
- 支持二维路线和三维地图查看。
- 能在户外沿 GPX 行进，并提供偏航提醒。
- 先通过电脑浏览器验证界面与核心逻辑，再推进移动端能力。
- 提供 Cesium、天地图、高德等地图选择。

**产品边界：** 沿 GPX 引导依据已有轨迹判断位置与偏离；道路导航依据道路网络重新规划。二者应分别设计，不能把任意 GPX 转换成少量途经点后宣称实现等价导航。

## 4. 技术架构与设计规范

**更新频率：架构、数据结构、接口或关键算法变更时。**

### 4.1 当前架构

```text
本地 GPX
  └─ 解析 Worker
      ├─ 原始文件与解析结果 → IndexedDB
      ├─ 分段与统计 → 工作台、海拔图
      └─ 显示几何 → Canvas / Cesium / 高德

模拟位置 / 浏览器定位
  └─ Guidance 匹配与偏航状态机
      └─ 状态面板、位置标记、声音/振动

浏览器
  ├─ Cesium / 天地图在线服务
  └─ Node.js 后端
      ├─ 公开地图配置
      ├─ 高德固定路径代理
      ├─ 管理员用量查询
      └─ dist 静态文件
```

高德运行在独立 iframe 中，以隔离地图实例生命周期；该方式不能视为安全沙箱。

### 4.2 代码职责

| 路径 | 职责 |
|---|---|
| `src/main.ts` | 页面编排、用户事件、路线选择和地图生命周期 |
| `src/core` | GPX、距离、分段、匹配、模拟、坐标与地图配置 |
| `src/adapters` | IndexedDB、浏览器定位、后端配置适配 |
| `src/ui` | Canvas、Cesium、高德渲染 |
| `src/parse.worker.ts` | GPX 解析与统计任务 |
| `server` | HTTP 服务、代理与服务端测试 |
| `scripts/dev.mjs` | 同时启动开发前后端 |
| `tests` | 算法、配置及地图适配回归 |

`main.ts` 同时承担多种职责。后续增加原生桥接前，应逐步分离导航会话、地图调度和页面展示。

### 4.3 数据与算法规范

| 规范 | 当前实现与要求 |
|---|---|
| 原始数据保真 | 保存原始 GPX；显示简化不能修改原始数据和统计 |
| 分段 | 不连接断段，不累计断段间距离；模拟到断口停止 |
| 坐标 | 核心数据使用 WGS84；高德显示边界转换为 GCJ-02 |
| 距离 | 使用 WGS84 椭球距离 |
| 海拔 | 不补造缺失海拔；海拔基准未知时不能当作已校准高程 |
| 爬升下降 | 当前使用 3 米滞回规则；海拔缺失会影响完整统计 |
| 时间 | 统计有效分段内记录时长，不等同于预计徒步耗时 |
| 导出 | 当前导出原始文件，不是重新生成当前单条路线或实走轨迹 |
| 本地数据版本 | 当前 Track schemaVersion 为 1；后续变更须设计迁移 |

GPX 当前边界：约 20 MiB 文件上限、20 万点上限、128 条轨迹上限、每轨迹 1,000 段、XML 深度限制及解析超时。仅包含航点而没有有效路线的文件不作为可行进路线导入。

### 4.4 引导规则基线

| 参数 | 当前值 |
|---|---|
| 定位精度门槛 | 精度大于 35 米进入不确定状态 |
| 位置过期 | 超过 10 秒 |
| 偏航进入阈值 | `max(40米, 2 × accuracy)` |
| 偏航确认时间 | 连续 5 秒 |
| 恢复阈值与时间 | 小于 20 米，持续 3 秒 |
| 定位中断 | 较长更新间隔重置连续确认时间 |
| 大幅跳点/跨断段 | 要求重新锚定 |
| 浏览器切后台 | 当前停止定位 |

上述为实现参数，不是经户外验证的最终产品指标。阈值调整必须保留原因、样本和回归结果。

### 4.5 后端接口与安全边界

| 接口 | 用途 | 边界 |
|---|---|---|
| `GET /api/health` | 进程健康 | 不证明地图供应商可用 |
| `GET /api/map-config` | 公开配置 | 返回公开 Web Key，不返回安全密钥；已配置不代表凭据有效 |
| `GET /api/usage` | 用量查询 | Bearer 管理员令牌；仅本进程代理统计 |
| `GET /_AMapService/v3/vectormap` | 高德地图代理 | 固定上游 |
| `GET /_AMapService/v4/map/styles` | 高德样式代理 | 固定上游 |

当前代理具有路径白名单、凭据覆盖、超时、响应大小限制、错误脱敏和内存限流。

必须保留以下边界：

- 正式构建禁止退回浏览器保存高德安全密钥的方式。
- 高德 Web Key 仍是客户端公开应用标识。
- Cesium、天地图仍由浏览器使用相应 token/Key。
- Origin/Referer 检查不能代替身份认证。
- 当前限流按实际连接 IP；反向代理后可能合并多个用户。
- 当前统计不是供应商账单或全量地图调用统计。

### 4.6 设计规范

- 地图故障、弱定位、位置过期、偏航与正常状态必须清晰区分。
- 降级后应明确展示当前地图与能力状态。
- 户外主操作采用可验证的大触控目标和足够对比度。
- 数据缺失显示“无数据/待补充”，不得用零值伪装。
- 地图切换应保持路线、分段、选点和有效位置一致。
- 地图资源需正确销毁，异步结果不能污染已切换视图。
- 凭据不得写入源码、测试、日志或版本库。
- 数据库及原生通信协议变更须有版本和迁移设计。

## 7. 发布与交付流程

**更新频率：每次发布；部署方式改变时立即更新。**

### 7.1 当前运行方式

| 场景 | 命令 | 说明 |
|---|---|---|
| 本地完整开发 | `npm run dev` | 前端 5173 + 后端 8787 |
| 仅前端开发 | `npm run dev:frontend` | 不代表完整代理链路可用 |
| 前端测试 | `npm test` | Vitest |
| 后端测试 | `npm run test:server` | Node.js 测试 |
| 生产构建 | `npm run build` | 类型检查和打包 |
| 生产服务 | `npm start` | 提供 dist、API、高德代理 |
| 静态预览 | `npm run preview` | 不提供后端代理 |

后端部分测试依赖构建产物，发布流水线须保证 `dist` 来自当前待发布版本。

### 7.2 建议发布流程

1. **确认范围：** 对应需求、缺陷及变更记录完整。
2. **建立版本：** 从可追踪提交构建，记录依赖锁文件和环境。
3. **执行门禁：** 前端测试、构建、后端测试、必要的浏览器回归。
4. **预发布联调：** 使用正式构建验证真实地图凭据及代理。
5. **配置部署：** HTTPS、进程守护、精确来源白名单、可信网关限流。
6. **检查静态边界：** 只发布构建产物，不公开项目根目录、密钥和日志。
7. **小范围验收：** 验证导入、地图、异常降级与数据保留。
8. **正式交付：** 发布版本说明、使用限制、反馈入口和回滚方案。
9. **发布后观察：** 监控错误、限流、地图用量及用户反馈。

### 7.3 发布阻断条件

- 存在凭据泄露、数据损坏或重要路线语义错误。
- 核心测试失败或构建与待发布代码不一致。
- 公网发布未完成真实高德代理及 HTTPS 验证。
- 户外版未完成真实定位、锁屏告警、离线核心和会话恢复验收。
- 无可用回滚版本或数据迁移回退方案。
